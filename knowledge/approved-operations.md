# Approved Operations Guidance

## Access requests

Access changes require an approved ticket, a named business or system owner, least-privilege scope, and documented expiration or review criteria. Privileged access should use a separate administrative identity where supported.

## Production changes

Production changes should have an approved change record, implementation plan, validation steps, rollback criteria, owner, and maintenance window before execution.

## Security incidents

For a suspected security incident, preserve evidence, record the affected identity and system, note timestamps and observed indicators, avoid destructive remediation, and escalate through the approved incident-response path.

## Backups and rollback

Before a high-impact configuration or data change, verify a recent recoverable backup or snapshot and confirm the restoration owner and rollback procedure.

This file contains example portfolio guidance only. Organizations should replace it with their own approved procedures before operational use.
